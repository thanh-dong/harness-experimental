Implementation notes — US-028b Event-Log Cutover

Story packet: docs/stories/epics/E05-event-log-durable-layer/US-028b-cutover/ · Decisions: 0008 (frame), 0009 (supersedes 0004) · Intake: #3 (new_initiative, high-risk)

design decision Design decisions

DecisionRejected alternativeWhy
Mutation order: apply-in-transaction → append+fsync → commit. Append-first, then apply. SQLite CHECK/PK constraints validate the event before it can poison the log (a bad --outcome never becomes a permanent log line). The crash window between append and commit leaves cache behind log — exactly the direction watermark replay heals. Apply-and-commit-first would allow cache ahead of log = silent drift.
The LWW guard lives in apply_story_update (a field applies only when the incoming (event_id, writer) exceeds the last update's). Order-by-arrival apply. Required for incremental replay to converge with full rebuild when an older concurrent event arrives after a newer one (clock skew + late pull). Proven by test: the late older event does not overwrite, and the collision is still audited.
Causal audit via per-event observed watermark snapshots (DKR-4's preferred option), weight 0 in the entropy score. git merge-base detection; wall-clock window; entropy-scoring collisions. Transport-agnostic and works at replay time without git. Wall-clock windows structurally miss skew > window. Weight 0: a resolved LWW collision is surfaced state, not drift — calibration goldens stay stable.
ULID id display is full-length; input accepts unambiguous prefixes. Parent spec's "prints short forms". A ULID prefix is its timestamp: any truncated display form is ambiguous precisely for burst-created rows and cannot be pasted back. Deviation recorded below.
import brownfield on a pristine event-backed cache seeds legacy-style then immediately re-runs migrate-to-events internally. Refusing outright; teaching the importer to emit events. Preserves the documented adoption flow (init → import) with a proven-genesis result, reusing the migration proof instead of a second event-emitting importer. Non-pristine event-backed caches refuse (decision 0008 Q4).
migrate-to-events demands current schema (migrate first). Auto-applying pending migrations inside it. The dogfood run caught this live: live INTEGER ids vs rebuilt TEXT ids failed the equality proof (the tripwire worked). Explicit ordering keeps migrate the single schema authority; the error now names the fix.

deviation Deviations

  • Id display: full ULIDs instead of the parent spec's "short forms" (rationale above; prefix input keeps the backlog close --id ergonomics).
  • US-028a's emit_shadow (warn-never-fail) was removed rather than kept dormant: post-cutover an unwritable log fails the command and rolls back the cache write — the flip is tested.
  • Generated views are markdown tables (parse-stable, diff-friendly) rather than preserving the old templates' instructional prose.

tradeoff Tradeoffs & accepted limits

  • Tool scan status (status, checked_at) resets to unknown on rebuild — machine-local reality is never logged; tool check re-scans.
  • Full rebuild is linear (~7.6 s at 100k events) — acceptable for the explicit fresh-clone/rebuild path; the per-command path is flat (~6.8 ms p95 measured at 100k, ~15× under the wall) thanks to the stat short-circuit built in from the start (DKR-2).
  • No file locking between two same-writer processes racing on one clone; O_APPEND keeps lines intact and a mismatched watermark heals via prefix-hash check or full rebuild. Single-user CLI risk accepted.
  • Log growth unbounded until US-028c (count-triggered compaction ~5k events; DKR-1 shows bytes are a non-issue for 24+ months).

open question Open questions
