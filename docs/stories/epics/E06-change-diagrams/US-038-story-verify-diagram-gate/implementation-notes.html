design decision Design decisions

ChoiceRejected alternativeWhy
Gate on any diagram file naming the story that is not reviewedGate only on flag-required diagramsThe CLI does not know the intake flags per story reliably; "if you drew it, it is reviewed or deleted" is simpler and stricter, with no configurability.
Filesystem scan of docs/**/diagrams/D<n>-*.md keyed on the Story: headerA diagram table / --diagrams field on story addNo schema, no event format change, no extra bookkeeping; the file header is already the readable source of status per DIAGRAMS.md.
Record a story.verify_result fail event when gatedReturn fail without recordinglast_verified_result must not claim a pass that never ran; traces that link the story get the existing advisory warning for free.
Gate only when a verify_command existsGate stories without a command tooKeeps the existing "no verify_command" error path unchanged; stories without commands are already skipped by verify-all.

deviation Deviations

  • None from the plan. The local binary at scripts/bin/harness-cli was rebuilt from source (0.1.15) so the gate could be proven live; the published release asset still needs the harness-cli-v0.1.15 tag pushed (US-025 flow), which is an outward-facing action left to the human.

tradeoff Tradeoffs & accepted limits

  • The scan walks all of docs/ on every verify; on this repo that is milliseconds. A very large docs tree could make verify-all noticeably slower — acceptable until observed.
  • Header parsing is line-prefix based, matching scripts/check-diagrams.sh; a malformed header counts as missing status and gates (fail-closed).
